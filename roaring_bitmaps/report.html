Варианты и датасеты

off

Без RunOptimize

Только массивы и битмапы. Базовая линия.

on

С RunOptimize

Серии значений схлопнуты в интервалы. Тот же код, одним вызовом больше. Сериализация и Rank/Select сравниваются со своими альтернативами.

sparse

200k случайных значений на 2³¹. Все контейнеры — крошечные массивы. Доминируют накладные расходы на контейнер.

runs

Серии по 512 значений с разрывами. Без RunOptimize — битмапы, с ним — интервалы. Данные, ради которых сделаны run-контейнеры.

zipf

Плотная голова, редкий хвост. Все три вида контейнеров в одном битмапе. Ближе всего к реальным данным.

Сериализация

raw — отсортированная копия значений рядом с битмапом: записывается как есть и читается обратно в такой же срез. roaring — портируемый формат Roaring, из контейнеров в контейнеры.

Размер

байт на значение

Сколько байт сериализованного потока приходится на одно значение набора.

ToBytes

запись

Сколько времени занимает превращение битмапа в памяти в срез байт.

FromBytes

разбор и восстановление битмапа

Сколько времени занимает восстановление из среза байт битмапа, с которым уже можно работать.

Rank / Select

array — отсортированная копия значений рядом с битмапом: бинарный поиск для Rank, индекс для Select. roaring — ответ из контейнеров плюс кэш префиксных сумм, по одному числу на контейнер.

Rank

сколько значений не больше данного

Сколько времени занимает ответ, сколько значений набора не превышают данное.

Select

i-е по порядку значение

Сколько времени занимает поиск i-го по порядку значения набора.

Что показали замеры

Медианы десяти прогонов, 200 000 значений в наборе. Разброс до 23%: разница меньше полутора раз — шум.

Run-контейнеры ускоряют операции над сериями в разы

And на runs — в 16 раз быстрее с RunOptimize. Серия значений — один интервал вместо цепочки битов, и пересечение интервалов не заглядывает в значения. Or, AndNot, Xor — от 3 до 8 раз.

Но точечные проверки становятся медленнее

Contains на runs — почти втрое медленнее. Бинарный поиск по интервалам вместо битового теста. При сплошных точечных запросах run-кодировка может не окупиться.

На случайных и смешанных данных разницы нет

На sparse и zipf RunOptimize не находит, что схлопывать, и оба варианта — один и тот же битмап. Все отличия — в пределах шума. Вызов сам по себе ничего не ускоряет, пока в данных нет серий.

Сериализация окупается только там, где есть серии

runs: поток в 500 раз меньше сырого дампа, запись и чтение — в 120–180 раз быстрее. На sparse и zipf готовая копия — просто проход по памяти, и она обгоняет формат по скорости; формат выигрывает лишь 0.7–1.9 байта на значение.

Rank/Select — это обмен скорости на память

Отсортированная копия отвечает на Select за 1.5 нс против 14–76 — индекс не обыграть. Зато она стоит 4 байта на значение, а кэш префиксов — от тысячных до 1.3. Rank вровень: на runs формат даже вдвое быстрее.

Что из этого следует

Есть серии — RunOptimize: выигрыш в разы по скорости, размеру и сериализации. Данные случайные — не вызывать: чуть быстрее точечные проверки, а сохранять дешевле сырым дампом. Нужна позиция без копии в памяти — Rank/Select.
