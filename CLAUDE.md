# CLAUDE.md

## Go Code Rules 

- выполняй задачи в отдельных ветках `feature/<feature-name>`, не в `main`/`master`
- Не удаляй код, который был написан после взятия задачи в работу, без согласования с автором.
- Используй go.uber.org/mock для генерации моков.


## Правила специфичные для юнит-тестов

- Использовать пакет `testing`.
- Использовать пакет `github.com/stretchr/testify/require` для проверки значений.
- Использовать табличные тесты.
- Название файла с тестами должно быть `<имя_файла>_test.go`.
- В случае, если передаваемый параметр не используется в функции, замени его имя на нижнее подчеркивание.
- Для моков используй библиотеку go.uber.org/mock/gomock.
- Для проверки значений используй require github.com/stretchr/testify/require.
- Название табличного теста должно быть в поле name.
- Тесты должны выполнятся с параллелизмом.
- Не мокируй вызовы функций из пакета логирования.
- Для входных значений используй тип args, в которой должны содержаться входные параметры тестируемой функции.
- В коде настройки моков использовать для вызовы каждого мока метод `Times`. Если мокируемая функция вызывается один раз использовать `Times(1)`.
- В коде настройки моков если тестируемая функция возвращает какое-то значение всегда использовать метод `Return`. Если мокируемая функция возвращает error, то вызывать Return(nil).
- В коде настройки моков при вызове методов идущих один за другим вызовы вызов нового метода переносить на новую строку.
- Старайся использовать минимальное количество комментариев. Пиши комментарии только на английском.
- Инициализируй переменную ctrl внутри цикла вызова тестов.
- Используй `assert.AnError` для проверки возвращения ошибки.
- Если название интерфейса начинается с прописной буквы, то и в имени мока оно также должно быть с прописной
- для генерации моков используй команду `mockgen -source=ports.go -destination=ports_mock.go -package=имя_пакета` в директории с кодом, где лежит файл ports.go
