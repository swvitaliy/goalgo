Одна структура данных, три реализации, общие SIMD-примитивы. v2 и v3 замеряются с RunOptimize. Разница между столбиками — цена и выигрыш каждой оптимизации.

Версии и датасеты

v1

Массивы и битмапы

Два классических контейнера. Базовая линия.

v2

+ run-контейнеры

Серии значений хранятся как интервалы. Включается явным RunOptimize.

v3

+ сериализация, Rank/Select

На set-операции не влияет: v3 ≈ v2. Сравнивается с сырым дампом uint32.

sparse

200k случайных значений на 2³¹. Все контейнеры — крошечные массивы. Доминируют накладные расходы на контейнер.

runs

Серии по 512 значений с разрывами. У v1 — битмапы, у v2/v3 — интервалы. Данные, ради которых сделан v2.

zipf

Плотная голова, редкий хвост. Все три вида контейнеров в одном битмапе. Ближе всего к реальным данным.

Rank / Select

Только v3. array — отсортированная копия значений рядом с битмапом: бинарный поиск для Rank, индекс для Select. v3 — ответ из контейнеров плюс кэш префиксных сумм, по одному числу на контейнер.

Rank

сколько значений не больше данного

Сколько времени занимает ответ, сколько значений набора не превышают данное.

Select

i-е по порядку значение

Сколько времени занимает поиск i-го по порядку значения набора.

Что показали замеры

Медианы десяти прогонов, 200 000 значений в наборе. Разброс до 16%: разница меньше полутора раз — шум.

Run-контейнеры ускоряют операции над сериями в разы

And на runs — в 17 раз быстрее у v2, чем у v1. Серия значений — один интервал вместо цепочки битов, и пересечение интервалов не заглядывает в значения. v3 повторяет v2.

Но точечные проверки становятся медленнее

Contains на runs — втрое медленнее. Бинарный поиск по интервалам вместо битового теста. При сплошных точечных запросах run-кодировка может не окупиться.

На случайных данных v2 и v3 немного проигрывают

На sparse серий нет, но v2/v3 отстают до полутора раз. Причина — контейнер 64 байта против 48: третий вид контейнера стоит одно поле, а операция создаёт их десятки тысяч.

На смешанных данных разницы нет

zipf: три версии в пределах шума. Выигрыш на плотных участках и потери на редких компенсируются. Переход на v2 сам по себе ничего не ускоряет, пока в данных нет серий.

Сериализация окупается там, где есть серии

runs: поток в 500 раз меньше сырого дампа, чтение — в 600 раз быстрее. На sparse сжимать почти нечего, но чтение всё равно втрое быстрее — контейнеры ложатся на место, а не собираются по одному значению.

Rank/Select — это обмен скорости на память

Отсортированная копия отвечает на Select за 2 нс против 14–75 у v3 — индекс не обыграть. Зато она стоит 4 байта на значение, а v3 — от тысячных до 1.3. Rank вровень: на runs v3 даже вдвое быстрее.

Что из этого следует

Есть серии — v2 с RunOptimize: выигрыш в разы по скорости и размеру. Данные случайные — v1 чуть быстрее и проще. Нужно сохранять, передавать или спрашивать позицию — v3.
